# 수익 모델과 매출 시나리오 — 자산 가치평가 인프라

SOM을 매출로 환산하는 단계입니다. TAM-SAM-SOM이 **기관 수**로 끝나면 사업계획서가 되지 않습니다. `기관 수 × 계약단가 = 매출`까지 내려와야 합니다.

> ⚠️ 아래 가격은 **시장에서 검증된 값이 아니라 국내 고객 구조를 근거로 한 추정치**입니다. 원본 리서치도 이 점을 명시하고 있습니다.

---

## 1. 가격 모델

### 상업용 부동산 — CRE Valuation API

| 플랜 | 월 단가 | 연 환산 | 대상 규모 |
|---|---:|---:|---|
| **Basic** | 200만 원 | 2,400만 원 | 자산 20~50개 |
| **Professional** | 400~700만 원 | 4,800만~8,400만 원 | 자산 100~300개 |
| **Enterprise** | 800~1,500만 원+ | 1억~1.8억 원+ | API + 실시간·일간 재평가 + 내부시스템 연동 |

### 디지털 자산 — Reference Price API

| 플랜 | 월 단가 | 연 환산 |
|---|---:|---:|
| **API Basic** | 300만 원 | 3,600만 원 |
| **Institutional** | 500~1,000만 원 | 6,000만~1.2억 원 |
| **Enterprise / Exchange** | 1,000~2,000만 원+ | **1.2~2.4억 원+** |

> 💡 거래소·수탁기관은 가격 데이터가 **핵심 시스템에 들어가면** 단순 SaaS가 아니라 **데이터 인프라 계약**으로 단가가 형성됩니다. 자산 규모가 아니라 **시스템 결합도**가 가격을 정하는 구조입니다.

## 2. 매출 시나리오

| | 시나리오 A<br/>보수적 | 시나리오 B<br/>PMF 달성 | 시나리오 C<br/>의미 있는 플레이어 |
|---|---:|---:|---:|
| 부동산 고객 수 | 5개 | 15개 | 30개 |
| 디지털 자산 고객 수 | 3개 | 8개 | 15개 |
| 부동산 평균 계약 | 4,000만 원 | 5,000만 원 | 6,000만 원 |
| 디지털 평균 계약 | 6,000만 원 | 7,000만 원 | 8,000만 원 |
| 부동산 매출 | 2.0억 | 7.5억 | 18억 |
| 디지털 매출 | 1.8억 | 5.6억 | 12억 |
| **합계 ARR** | **약 3.8억 원** | **약 13.1억 원** | **약 30억 원** |

여기에 데이터 라이선스, API 호출량 과금, 신규 자산 평가비, 커스터마이징을 더하면 **30~50억 원대** 매출 구조가 가능하다는 것이 원본의 결론입니다.

### SOM과의 정합성

| | SOM 목표 | 시나리오 대응 |
|---|---|---|
| 고객 수 | 20~50개 기관 | 시나리오 B(23개) ~ C(45개) |
| 매출 | 10~30억 원 ARR | 시나리오 B(13.1억) ~ C(30억) |

시나리오 B~C가 SOM 구간과 맞물립니다. 시나리오 A(8개 기관, 3.8억)는 SOM 하한에도 못 미치므로, **실질적으로 SOM은 "PMF를 달성한 경우"를 전제로 잡혀 있습니다.**

## 3. 검토

### 구조적으로 잘 된 점

**① 계약단가가 자산 규모에 연동됩니다** — Basic(자산 20~50개) → Professional(100~300개) 식으로 고객의 자산 수에 따라 플랜이 올라갑니다. AMC처럼 자산이 많은 고객이 자연스럽게 상위 플랜으로 가는 구조입니다.

**② 디지털 자산의 단가가 더 높게 잡혔습니다** — 고객 수는 적지만(27개사) ARPU가 높다는 세그먼트 판단이 가격에 반영되어 있습니다. 앞선 세그먼트 맵과 일관됩니다.

### 짚어야 할 점

**① 시나리오 A가 SOM에 못 미칩니다**
SOM 하한이 20개 기관·10억 원인데 시나리오 A는 8개 기관·3.8억 원입니다. **보수적 시나리오가 목표 하한을 밑돈다면, SOM 하한 자체가 보수적이지 않다는 뜻입니다.** 사업계획서에서는 시나리오 A를 SOM의 하한으로 다시 맞추거나, SOM 범위를 아래로 넓히는 편이 정직합니다.

**② 이탈률(churn)과 도입 기간이 빠져 있습니다**
ARR 모델인데 갱신율 가정이 없습니다. B2B 데이터 인프라는 파일럿 → 내부 검증 → 시스템 연동까지 통상 6~18개월이 걸립니다. 3년차에 30~45개 기관을 확보하려면 **1년차부터 파이프라인이 돌아야** 하는데, 그 리드타임이 시나리오에 반영되지 않았습니다.

**③ 가격 폭이 넓습니다**
Enterprise 기준 부동산 1~1.8억, 디지털 1.2~2.4억으로 최대 2배 차이입니다. 이 폭이 SAM의 5.7배 편차(30~170억)로 이어집니다.

## 4. 다음 단계 — 원본이 제시한 검증 순서

```
고객별 실제 지불의사(WTP)
        ↓
   예상 계약단가
        ↓
    고객 Top 30
        ↓
   3년 매출 Forecast
        ↓
    TAM / SAM / SOM
```

특히 두 질문을 검증하면 추정 폭이 크게 좁혀집니다.

- **AMC 1곳이 실제로 얼마를 지불할 것인가?**
- **거래소 1곳이 가격 API에 얼마를 지불할 것인가?**

> 💡 **순서에 주목하십시오.** TAM-SAM-SOM이 **맨 마지막**입니다. 시장 규모를 먼저 잡고 고객을 끼워 맞추는 게 아니라, 고객의 지불의사에서 출발해 위로 쌓아 올립니다. 이것이 Bottom-up 산정의 실제 작업 순서입니다.
